# 影之刃零修改器 v0.13.1

Windows 64 位修改器，支持中文界面与单文件 EXE。连接时校验游戏版本，所有修改功能默认关闭。

**[下载 v0.13.1](https://github.com/sdkdsd/PBZ-Trainer/releases/tag/v0.13.1)** · [更新记录](CHANGELOG.md) · [验证记录](VALIDATION.md)

修复了一些已知bug

## 下载与使用

1. 打开 Release 页面，在 Assets 中下载 `PBZ-Trainer-v0.13.1.exe`。
2. 进入可以操作角色的场景后双击 EXE，程序会尝试连接游戏。
3. 按需开启功能。无需安装 Python，也不需要额外的配置文件或 runtime 文件夹。

当前支持 **Steam build 26266538** 的 Windows x64 主程序；其他版本需要重新适配。

## 随地传送解锁

**游戏会提示消耗穿行符（传送符），但实际不消耗。** 正常确认即可；已有穿行符记录且数量为 0 时同样可用。

在地图中选择已激活且可传送的目的地。保留游戏原有战斗、剧情及其他可传送条件，不解锁未激活目的地。此开关独立于锁血，关闭传送开关不影响生命保护。

## 功能

| 功能 | 范围与说明 |
| --- | --- |
| 强锁血 | 维持生命下限，与自动回血互斥 |
| 自动回血 | 受伤后补满，不能保证阻止一击致死 |
| 锁杀气、暗源、精纯杀气 | 消耗后按需补满，不改变容量 |
| 锁葫芦／酒次数 | 补满已有药品次数；图标可能需切换快捷药品刷新 |
| 单次补充 | 回满生命、补充葫芦、补满精纯杀气 |
| 玩家基础攻击倍率 | 0.1–20 倍，调整基础攻击，最终伤害由游戏计算 |
| 一键秒杀 | 基础攻击 ×10000，与普通倍率相互替代；特殊敌人及剧情规则仍按游戏处理 |
| 怪物伤害倍率 | 0.1–20 倍，调整玩家物理／元素承伤，不包含特殊真实伤害 |
| 移动加速 | 1–5 倍；冲刺被游戏重算后可能需重新应用 |
| 武器切换冷却 | 0.1–2 秒；换装备后需重新应用 |
| 随地传送解锁 | 会提示消耗穿行符，但实际不消耗 |
| 意识尘埃数量 | 0–2,000,000,000，支持撤销同一窗口上次设置 |

## 场景切换与恢复

强锁血与攻击倍率保留开启请求，加载或角色暂不可读时暂停写入；当前角色稳定后重新绑定。攻击维持本次设置的固定目标，避免重复叠乘。其他资源锁在对象切换时可能停止，需要重新开启。

“恢复移速”只恢复移动速度；底部恢复按钮同时管理倍率、移速、武器切换冷却和生命下限。正常退出会停止本窗口的资源锁，条件恢复本窗口记录的修改及传送分派。意识尘埃可能随自动存档保留，不随关闭回退。新窗口不会接管其他修改器已开启的功能，请勿同时用多个面板控制同一项。

传送校验心跳超过约三秒未更新时转交原游戏行为；适配页保留到游戏退出，避免正在执行的调用访问已释放内存。正常退出会条件恢复对应分派指针。

## 错误提示与恢复（fork 新增）

界面底部除原有消息行外，新增一行**错误状态栏**，颜色取当前最高等级：

| 颜色 | 等级 | 含义 | 程序做了什么 / 你该怎么做 |
| --- | --- | --- | --- |
| 不显示 | 目标失效 | 切场景、角色未就绪、对象已切换等暂时情况 | 自动等待重新绑定，无需处理 |
| 灰色 | 日志异常 | `actions.jsonl` 写不进去（磁盘满、无权限） | 修改照常进行，但审计记录可能缺失；检查日志目录 |
| 黄色 | 读取失败 | 连续约 20 次读不到游戏内存 | 确认游戏仍在运行、角色可操作 |
| 黄色 | 写入失败 | 写入失败或读回不一致 | 对应功能已停止或停用，需要时重新开启 |
| 红色 | 版本校验失败 | 游戏版本或映像与已核对版本不符 | 拒绝连接，不会写入；需要新版适配 |
| 红色 | 回滚失败 | 写入失败后，恢复原值也失败，**游戏里可能残留修改** | 首次出现会弹窗；撤销记录已保留，按下面步骤恢复 |

- 状态栏显示各类计数和最近一条；点 **“详情”** 查看最近 5 条。
- 红色提示**不会被普通消息覆盖**，必须点 **“已知晓”** 才会清除。“已知晓”只清除提示，不会改动游戏数据。
- 出现回滚失败时，点 **“恢复残留修改”**（与底部“恢复倍率、移速、冷却与锁血”相同）重试恢复已保留的记录。已恢复的条目会从记录中删除，重复点击不会重复写入。恢复仍然失败时，消息行会列出每一项的原因；也可以等角色稳定后再试，或查看日志。
- 强锁血、攻击倍率因写入或回滚失败被停用时，状态文字显示“已停用”，强锁血开关会自动取消勾选；确认问题后重新开启即可。只有角色暂不可读时才显示“暂缓”，并在角色稳定后自动继续。

EXE 日志保存在 `%LOCALAPPDATA%/PBZTrainer/logs/actions.jsonl`；源码模式使用源码目录的 `logs/`。

## 代码结构（fork 重构）

**对玩家无可见变化**：功能、界面、日志与报错文案都与重构前一致。代码按层拆分（只允许上层依赖下层，`test_structure.py` 用 AST 检查）：

| 层 | 文件 | 职责 |
|---|---|---|
| 偏移表 | `offsets.py` | 所有字段偏移、对象链偏移、数值上限（唯一的硬编码偏移来源） |
| win32 | `win32.py` | Windows API 绑定 |
| memory | `memory.py` | 打开进程、读写内存、`DataWriteError` |
| ue | `ue.py` | UE 对象/反射/名称解析、`map_rows`/`_sparse_rows` TMap 解析 |
| writer | `writer.py` | 写前日志、写入、条件恢复 |
| features | `features/targets.py`、`modifiers.py`、`resources.py` | 定位玩家目标、数值修改、资源锁（`ResourceLock` 配置表） |
| core | `core.py` | `Game` 由上述 mixin 组合；版本校验、传送入口；重新导出旧名字，旧的 `from core import ...` 照常可用 |

## 游戏更新后怎么改偏移

1. 先改 `profile.json`（版本号与指纹），没有匹配的指纹时修改器会拒绝连接。
2. 字段偏移变了：只改 `offsets.py` 里对应的 `Field(...)`/`AttrField(...)` 常量；每个字段都带所属类名和属性名，运行时会先用反射核对，不一致就报错而不是乱写。
3. 本地跑测试（见下），golden trace 会因为偏移变化而失败，确认差异只是新偏移后用 `python test_golden_trace.py --update`重新生成，并在 `docs/CHANGES.md` 记录。
4. 仍需实机验收：CI 绿不等于游戏里可用。

### 测试与 golden trace

`tests_golden/trace.json` 记录了 30 个假内存场景下的每一次读、写、日志和报错。纯重构提交必须让它逐字节不变；`test_offsets.py` 还会检查 core.py/session_effects.py 里不再出现已迁移的十六进制偏移。

## 设置保存（fork 新增）

修改器会记住你上次填的四个数值，下次打开时自动填回输入框，不用重新输入。

- **保存什么**：玩家攻击倍率、怪物伤害倍率、移动速度、武器切换冷却这四个输入框的数字；以及上次开过哪些开关的**名字**（只用来显示一行提示）。
- **不保存 / 不恢复什么**：
  - 九个开关（强锁血、自动回血、锁杀气、锁暗源、锁葫芦、锁酒、锁精纯杀气、一键秒杀、随地传送解锁）每次启动**都是关闭**的。界面会显示一行文字，例如"上次开过：强锁血、锁杀气（仅提示，本次均未开启，需要时请手动打开）"，但绝不会自动勾选或开启。
  - 窗口大小和位置、意识尘埃数量（每次读游戏当前值）、状态文字和错误记录都不保存。
- **不会自动改游戏**：填回的只是输入框里的数字，仍然要你点对应的"应用"按钮才会写进游戏内存。上次如果用了很高的倍率（比如攻击 20），打开后会看到 20，请确认再应用。
- **什么时候保存**：点"应用"且写入成功后，以及正常关闭修改器时。
- **文件位置**：EXE 版 `%LOCALAPPDATA%\PBZTrainer\settings.json`；源码模式为仓库目录下的 `settings.json`（已加入 `.gitignore`）。环境变量 `PBZ_TRAINER_SETTINGS` 可指定其他路径。
- **怎么重置**：关闭修改器后删除 `settings.json`，下次启动就是默认值（2.0 / 1.0 / 1.5 / 0.1）。
- **出错时**：文件损坏会被改名为 `settings.json.bad-<时间>` 保留，改用默认值，状态栏灰色提示一次；某一项数字越界或不是数字，只有这一项回到默认值；文件来自更新的版本时用默认值，且不会覆盖它；保存失败只在状态栏灰色提示，不影响修改器使用和关闭时的恢复流程。
- `--self-check` 和 `--preview` 模式不读也不写设置文件。

## 启动校验缓存（fork 新增）

连接游戏时，修改器要确认 `pbz.exe` 正是 `profile.json` 里核对过的那个版本（SHA256）。原来每次连接都把几百 MB 的 exe 整个读一遍；现在第一次完整校验通过后，会把结果和文件身份一起记进缓存，之后文件没变就直接命中，基本秒连。

- **缓存位置**：EXE 版 `%LOCALAPPDATA%\PBZTrainer\hash-cache.json`；源码模式为仓库目录下的 `hash-cache.json`（已加入 `.gitignore`）。
- **文件身份**：路径、大小、修改时间、创建时间、NTFS 文件 ID、卷号，以及 exe 文件头里的 PE 时间戳。任何一项变了（比如 Steam 更新、替换文件）都会重新完整计算。
- **只会多算，不会放行**：只缓存"完整计算并且与 profile 一致"的结果；命中后仍要和 profile 期望值比较；缓存损坏、格式不认、写不进去，都只是退回完整校验。版本不对时照旧拒绝连接，报错文字不变。
- **还有第二道校验**：不论是否命中缓存，连接时都还会检查进程映像路径、PE 头、64 位、映像大小和引擎名称池。
- **连接提示**：连接成功的提示会写明"版本校验：缓存命中"或"版本校验：完整校验"。
- **强制完整校验**：`python app.py --no-hash-cache`（EXE 版同样可加此参数），或设环境变量 `PBZ_TRAINER_NO_HASH_CACHE=1`。`--self-check --check-game` 始终完整校验。
- **重置**：直接删除 `hash-cache.json`，下次连接会完整计算并重建。
- **校验强度说明**：比每次完整哈希略弱。理论上，若有人原地改写 exe 内容，同时保持大小不变、刻意回拨修改时间，且文件 ID、创建时间、PE 时间戳都不变，就能骗过缓存；正常 Steam 更新不会出现这种情况，而且映像大小与名称池校验仍会兜底。缓存不加签名：能改缓存的人同样能直接改 exe 或修改器本身。担心时用 `--no-hash-cache`。

## 从源码运行与构建

使用带 Tk 的 Windows x64 Python 3.13：

```powershell
python app.py
python app.py --preview
```

构建单文件 EXE：

```powershell
python -m venv .build-venv
& ./.build-venv/Scripts/python.exe -m pip install -r requirements-build.txt
./build_exe.ps1
```

输出为 `dist/影之刃零修改器.exe`，内含运行环境、版本配置、原创图标及许可。

本地检查：

```powershell
python -m unittest discover -s . -p 'test_*.py'
python app.py --self-check --report ui-check.json
```

自检不连接游戏；`--check-game` 额外进行阻断写入的只读连接检查。许可证可在“使用说明”中查看，原文见 [THIRD_PARTY_NOTICES.txt](assets/THIRD_PARTY_NOTICES.txt)。

## 持续集成（fork 新增）

本 fork 在 GitHub Actions 上用 **windows-latest + Python 3.13** 自动跑测试。

| 触发 | 跑什么 |
| --- | --- |
| push 到 `main` / `master` / `step*`，或打开/更新 PR | **test**：全量 `unittest` + `app.py --self-check` |
| 手动 `workflow_dispatch`，或推送标签 `v*` | 上述 test，外加 **build**：`build_exe.py` 产出 EXE |

- Actions 页可下载 artifact：`ui-check`（自检 JSON，失败也会尽量上传）；手动打包时还有 `pbz-trainer-exe`（EXE + `build-report.json`，含各输入文件 SHA256，保留 14 天）。
- **CI 绿 ≠ 实机已验收。** 流水线不装 Steam、不连游戏、不跑修改功能实机验收；只验证假内存单测与界面自检（开关默认关闭等）。游戏内行为仍需在 Windows 上人工确认。
- 权限仅 `contents: read`；不会自动发 Release，也不会向原作者仓库提 PR。
- fork 改动说明按**功能**分节（见 `docs/CHANGES.md`），不以内部步骤号为主标题。
